# 接口测试用例设计（JobRadar HTTP API）

被测对象：`api.py`（FastAPI，4 个端点）。自动化实现：`tests/test_api.py`，共 **24 条**。

设计思路：先用等价类把入参空间切成有效/无效两块，再用边界值把 `page` / `page_size` / `min_score`
的上下界各取一个，最后用场景法覆盖「鉴权 × 参数合法性」的组合。

## 一、端点清单

| 方法 | 路径 | 鉴权 | 主要分支 |
|---|---|---|---|
| GET | `/health` | 否 | 200 |
| GET | `/api/companies` | 否 | 200 列表 / 200 空列表 / 422 参数非法 |
| GET | `/api/companies/{company}` | 否 | 200 / 404 |
| POST | `/api/scores` | `X-API-Key` | 201 / 401 / 422 / 500 |

## 二、用例表

### 1. 健康检查

| # | 用例 | 设计方法 | 入参 | 预期 |
|---|---|---|---|---|
| 1 | 健康检查返回服务状态 | 正常等价类 | 无 | 200，含 `status=ok`、`companies`、`version` |

### 2. 列表查询：有效等价类

| # | 用例 | 设计方法 | 入参 | 预期 |
|---|---|---|---|---|
| 2 | 默认分页 | 默认值 | 无 | 200，`page=1`、`page_size=10`、`total` 正确 |
| 3 | 分页切分不重不漏 | 场景法 | `page=1/2, page_size=3` | 两页无交集，条数之和 = total |
| 4 | 页码超出末页 | 边界值（上界外） | `page=99` | 200，`items=[]`，`total` 不变 |
| 5 | 按最低匹配度过滤 | 等价类 | `min_score=80` | 只返回达标公司 |
| 6 | 按方向过滤 | 等价类 | `direction=测试` | 只返回命中该方向的公司 |
| 7 | 方向不存在 | 无效等价类（业务层） | `direction=不存在` | **200 且空列表**，不是 404 |
| 8 | 只看建议投递 | 等价类 | `only_suggest=true` | 只返回含「建议」记录的公司 |

> 用例 7 是刻意的设计决定：查询条件没命中是「结果为空」，不是「资源不存在」，
> 所以不该返回 404。这条最容易在实现里写错。

### 5. 写接口：鉴权与校验的组合

| # | 用例 | 设计方法 | 入参 | 预期 |
|---|---|---|---|---|
| 19 | 不带 key | 场景：鉴权失败 | 无 `X-API-Key` | 401 |
| 20 | key 错误 | 场景：鉴权失败 | `X-API-Key: wrong` | 401 |
| 21 | key 正确但缺必填字段 | 场景：鉴权通过 × 参数非法 | 无 `company` | 422 |
| 22 | key 正确，新增成功 | 场景：正常写 | `company=戊` | 201，`total` +1 |
| 23 | 同名公司更新不重复插入 | 幂等/场景 | 重复提交 `甲公司` | 201，`total` 不变，字段被更新 |
| 24 | 服务端未配置 key | 异常分支 | `API_KEY=""` | 500，而不是静默放行 |

## 三、几个刻意的取舍

- **没有测「数据库连接失败」**：本服务把数据放在 JSON 文件里，没有数据库，测它就是凭空造场景。
- **没有测并发写**：`save_companies` 是全量覆盖写，并发下确实会丢更新。这是一个**已知缺陷**，
  应该开缺陷单而不是写一条必过的用例来假装测过。
- **用 TestClient 而不是起真实端口**：CI 里更快更稳；真实部署后的冒烟用 `--base-url` 另行覆盖。

## 四、还没做的（已知缺口）

| 缺口 | 为什么 |
|---|---|
| 并发写一致性 | 需要真实并发与锁，单测环境不适合构造，应作为缺陷单独跟踪 |
| 大数据量分页性能 | 需造 10 万条数据，属于性能测试而非接口功能测试 |
| 部署态冒烟 | 需要真实端口与反向代理，放在冒烟脚本里跑 |
